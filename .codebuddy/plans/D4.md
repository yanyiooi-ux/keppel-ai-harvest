# D4 plan: the new look in Story mode, YY's two labels, the flow page and the video

Part D4 of the story mode plan (16 Oct 2026). YY: "drop the working name and use asset operations manager", then,
after seeing the one-page flow diagram: "can u add in the diagram and also the video onto the demo".

## Who uses it, and what decision it serves

- Judges (Keppel and Tencent Cloud experts) decide in a few minutes whether Pill Desk works and is useful. The
  flow page answers "who presses what, and who is told next" on one page; the video is the 6-minute walk-through.
- YY shows /demo, /flow and the video in the submission.

## Style options

None to pick: the look is locked. YY picked dark glass on 15 Oct (S23, D3: Geist, frosted panels, Bolt Pip).
Story mode and the new /flow page move onto the same tokens; no new style menu.

## Hard limits (not questions)

- No engine change: engine output, API shapes, pill text, the safety stop wording, tips and every reason string
  that feeds a saved AI answer's replay key stay byte for byte. web/data/replay/ is never touched.
- The new seat name is a render-layer change (plain words), never an engine change. The code id aom-tower-a and
  engine sentences ("the AOM ...") stay; the glossary line under them says what AOM means.
- Every colour is a token in :root (tests/c5a.test.tsx). Status colours carry their word.
- Engine and data tests stay byte for byte; web/tests/setup.ts too. Old UI tests that pin "working name",
  "Building manager (AOM)" or its variants, or a Neon Quest value, may change to the new value only, each listed
  old to new in the build log.
- The video file is never committed (web/public/media/*.mp4 is ignored).

## Phases

1. Merge d3-dark-glass into main by hand: both build log rows kept in date order; D3's tokens, font and Pip win;
   D2's Story mode code and CSS stay. Then Story mode on dark glass: the caption panel and the stage are frosted
   panels (--panel, --line, --r-panel, the shine and the blur), Play is the white main action (--main,
   --main-ink), Back, Next and Restart are quiet glass (--btn-bg), the step count is a muted sentence-case label,
   the progress bar and the outline use the violet. Tests and build, then the merge commit.
2. YY's labels: the top bar shows "Pill Desk" with no tag. SEAT_WORDS, the chat-head label, the A4 approval word,
   the glossary, the raised-stop line, the money rule and effect words, /how's lines and the story captions say
   "Asset Operations Manager". A grep over web/app and web/lib finds neither old string.
3. /flow, "How a job flows": the diagram's sections in the app's look, Bolt Pip in the header. Button and cause
   names come from the code (demo buttons in a new web/lib/flow.ts that reads CHARGE_CHOICES, PART_TITLES,
   causeLabel, SELF_CHECK_QUESTIONS, SEAT_WORDS and the story's own press labels where they exist). A test renders
   /flow and checks every button name on it is a real label: the text of a button in a component, or a label in
   one of those constants. Linked from home, /how and /demo.
4. The video: one component, a native video with controls, preload metadata and a poster frame, on home, /how
   and /flow, playing /media/pill-desk-video.mp4. The server checks the file exists; when it is missing the page
   shows "The video is not on this copy of the demo." A README in web/public/media says how to put it there.
   The poster frame is a small JPEG taken from the video (committed); the video is not.
5. Tests (npx vitest run --maxWorkers=4 --minWorkers=1), the build, demo-flow's line; render on a production
   build (port 4910, REPLAY_MODE=1): home, /how, /flow, /demo at steps 1, 4 and 8 and the five seats at 1280 and
   390; every PNG looked at; no sideways scroll at 390; 44 px touch targets.
6. Commits: the merge; "feat: YY's labels, the flow page and the video player [D4]"; "docs: proof for D4".
