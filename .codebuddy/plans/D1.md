# D1: plain words everywhere, and loading you can see

Part D1 of the story mode plan (15 Oct 2026). YY saw the finished app and said it is confusing to show: nothing
shows it is working when you press a button, and some words are too hard to read. He picked plain words
everywhere. D2 (Story mode at /demo) comes after this part and reuses what it builds.

## Hard limits (not questions)

- Plain words are a render-time layer. Engine output, API response shapes, pill text, the safety stop wording
  (S11, word for word), the tips and every code reason that feeds a saved AI answer's replay key stay byte for
  byte. Nothing under web/lib changes except the new pure module web/lib/plain-words.ts.
- Red stop cards keep their pill words untouched. Only the small label above them (the stop's code) gets a plain
  name next to it.
- Receipts (the small grey "Code · pill v1.0 · AI calls: 0" line) stay as they are: they already are the grey
  trace line.
- Engine and data tests stay byte for byte. An old UI test that pins a word this part replaces is updated to the
  new word only, and each one is listed old to new in the build log row.

## Build

1. web/lib/plain-words.ts (new, pure, safe in the browser). One map from every code a judge can see to plain
   words, each derived from the pill's own rule, step and stop text:
   - rule ids TS-CC-01 to TS-CC-26 (v1.0), TS-CC-27 (the demo's new rule, the v1.1 fixture), and a fallback for a
     later new rule;
   - red stops RS-01 to RS-10 (a short name only, never a new instruction);
   - lead tiers (found, signed-rule, case-backed, low-confidence, net-failed);
   - job statuses (all 11), notice kinds (all 10), approvals A1 to A4, seat ids, HQ's approval checks;
   - facts (the menu facts and every fact label) and effects (block step 25, put-first on each menu step).
   Each rule and step entry carries a key word that must appear in the pill's own text, so a test can check the
   plain word is grounded. A tokenizer splits a text into plain parts and codes (TS-CC-nn, RS-nn, "(A1)" to
   "(A4)", spec refs like "(S3)").
2. web/app/components/Plain.tsx (new): `CodeTag` (the small grey tag), `Plain` (a text with each code shown as
   its plain words, then the grey tag) and `Coded` (a plain label followed by its code tag).
3. Screens, plain words first and the code as a grey tag after it:
   - ChatCard runs its label, title, body, meaning and AI line through `Plain`; a red card only its label.
   - Seat chat: the seat tag, notice kinds, the Safety list, the input's placeholder.
   - Technician and senior manager desks: job statuses, tier badges, "Likely causes" headings, check and fix
     labels, removed reasons, checklist steps, facts, effects in the pickers, the outside help card, the new
     solution's label.
   - HQ desk: the A1 card, the approval headings, the solution card, the condition lines, the gates, the versions
     card, outside help, the Building B card.
   - AOM desk: charge requests, alerts, open stops.
   - Home, the Building B card on home, /how (the approvals list, the brain card, the safety list, the demo bar).
   - Top bar: "Head office (HQ)" and "Building manager (AOM)".
4. Loading you can see (SeatChat, the top bar, the /how bar, the AI switch):
   - every press and every typed message marks the pressed control (aria-busy and a small spinner) and shows
     "Pip is checking" with typing dots at the end of the chat;
   - while the request is on its way, every control in the chat is disabled (one disabled fieldset), so
     nothing double-fires;
   - the reply lands as soon as the server answers and the lock lifts with it; the mark and "Pip is checking"
     stay on screen at least 400 ms from the press (and as long as the server is slow). Decided while
     building: holding the reply itself back for 400 ms broke 5 old UI tests that press twice in a row or
     read the reload right after a press (run rule: an old test failing for a reason other than a replaced
     word means the code is wrong), so the reply is never held back;
   - a press or message that fails on the network shows a plain "not done" line instead of hanging;
   - new cards and messages fade and slide in for about 220 ms, only what lands after the first paint (a
     class the chat adds to new nodes), so the page opens still; prefers-reduced-motion turns it off.
   - The /how bar's and the top bar's Reset demo show the same pending state until the page reloads.
   - Found while building: "Pip never approve anything" read badly; on screen it now reads "Pip will never
     ...", the line itself (seat-opening.ts, the table the server checks) is unchanged.
   - Found while building: the safety alert notices carry the stop's own words, so they never go through
     the plain layer either; HQ's 4 approval checks show plain words with their id as the tag (one of them
     showed a function name, loadAndCheckPill).
5. CSS in web/app/globals.css: every new colour is a token in :root (tests/c5a.test.tsx).

## Tests (failing first)

- tests/d1-plain-words.test.ts: every rule id in the v1.0 pill and the v1.1 fixture, every red stop, every tier,
  job status, notice kind, approval, seat id, menu fact, fact label and menu effect has a plain word that is not
  the code itself; each rule and step word's key appears in the pill's own text; no plain word is over 20 words,
  holds an em dash or an unexplained acronym; the tokenizer finds the codes in real engine strings and gives back
  the same text when the plain words are taken out; the safety stop wording never goes through it.
- tests/d1-pending-ui.test.tsx (fake fetch): a press marks its button busy, disables the chat, shows "Pip is
  checking" for at least 400 ms, and a second press while pending sends nothing; a slow server keeps it locked
  and checking; the same for a typed message; a network failure shows "not done" and frees the controls; the
  /how Reset demo is busy and fires once; a lead card shows the plain tier word and the code tag; a notice
  shows its plain kind; a safety alert and a red stop keep their own words; only new cards get the move-in
  class; the grey tag's token pair clears 4.5:1.
- Old UI tests that pin a replaced word: new word only, listed in the build log row.
- web/tests/demo-flow.test.ts must still print "demo flow: all steps passed".
