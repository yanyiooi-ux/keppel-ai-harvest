# What the submission needs

Summarised from the hackathon handbook (pages 37 to 40) and the Keppel challenge statement. Our words, not the
handbook's.

## Hard gate
- The project must be original and built on CodeBuddy or WorkBuddy.
- Proof of CodeBuddy or WorkBuddy use is mandatory: chat screenshots, API call logs or a written description of the
  development process. Without proof, the project is not scored.

## Required in the form
| Item | Note |
|---|---|
| Project title | The name of the AI agent project. |
| Short blurb | What it does or the value it gives. **Under 10 words.** |
| Project description | Four parts: overview (scenarios, users, value); real-world insight (where the pain comes from, who has it, the core problem); solution design (business and technical architecture, and how prompts drive the AI); business value (numbers or clearly defined impact). |
| CodeBuddy or WorkBuddy chat history | At least 3 screenshots, or a screen recording, of chats during development. |
| Cover image | 16:9, about 380 by 216 px, for the online showcase. |

## Optional in the form (we do both)
| Item | Note |
|---|---|
| Demo video | 5 to 8 minutes: project overview, the core agent features and how they are used, and a short reflection on how we built with CodeBuddy, with tips. |
| Project link | A live URL. Optional, but it earns bonus points. |

## Required by the Keppel challenge
- **Demo walkthrough:** a live demonstration.
- **Solution diagram** answering 8 questions: the business problem; whose expertise is captured and how undocumented
  knowledge is obtained; how it becomes reusable; how an Asset Operations Manager uses and supervises it, checks its
  recommendations and knows when to escalate; why it is more than a chatbot or search tool; how feedback, outcomes and
  new expertise are reviewed, validated, versioned and approved; how it extends to more assets, business units or the
  enterprise; a credible path to build it with current or near-term technology.
- **Source code:** complete, in a GitHub repository.

## Judging
- Preliminary judging: Keppel and Tencent Cloud experts, on track criteria shared after registration
  (`track-criteria.md`).
- Demo Day criteria, 10 points each: Impact and Relevance, Human-Centered Design, AI Interaction, Technical Execution
  (quality and completeness), Feasibility, Demo and Storytelling, Innovation and Creativity, UX and Accessibility,
  Responsible AI and Ethics, Overall Quality.
